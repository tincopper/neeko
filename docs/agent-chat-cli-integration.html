架构总览：Agent Chat 的定位

Neeko 的 Agent Chat 不是简单的"终端包裹"——它是一个多 Agent 统一会话层，将不同 Agent CLI 的原生 IO 形态 (stdio JSON-Lines、JSON-RPC、HTTP SSE) 统一翻译为前端可渲染的 StreamEvent 协议。

核心设计原则

  • IO 形态正交：Adapter 内部自行决定 Spawn / Connect / SSE / ACP，契约不绑定 stdout/JSON-Lines
  • 开闭原则 (OCP)：新增 Agent = 新增 Adapter，协议层和页面不动
  • 薄命令层：Tauri Command 只做反序列化 + 调度，核心逻辑在 Adapter/Bridge

Agent 配置注册：AgentConfig 与 AgentManager

每个 Agent 在系统中以 AgentConfig 结构体注册，由 AgentManager 统一管理。

AgentConfig 关键字段

// src-tauri/src/common/agent/types.rs
pub struct AgentConfig {
    pub id: String,              // 唯一标识: "opencode", "claude-code", ...
    pub command: String,          // 可执行命令: "opencode", "claude", ...
    pub prompt_args: Option<Vec<String>>, // 前置参数: ["run", "--pure"]
    pub post_prompt_args: Option<Vec<String>>, // 后置参数
    pub chat_transport: Option<String>, // 传输协议: "acp" | "serve" | "jsonl"
    pub models: Vec<String>,     // 支持的模型 ID 列表

}

适配器工厂：adapter_for 的分派逻辑

adapter_for() 是整个对接触发的核心分派函数, 根据 Agent ID 和 chat_transport 选择对应的 Adapter。

// src-tauri/src/agent/chat/adapter.rs
pub fn adapter_for(
    agent_id: &str,
    transport: Option<&str>,
    cmd: Vec<String>,
) -> Result<Box<dyn AgentAdapter>, AppError> {
    // 1. mockAgent -> 进程内 ACP 模拟
    if agent_id == "mockAgent" {
        return Ok(Box::new(AcpAdapter::mock()));
    }
    // 2. 按 chat_transport 分派
    match transport {
        Some("acp")  => Ok(Box::new(AcpAdapter::new(cmd))),
        Some("serve") => Ok(Box::new(ServeAdapter::new())),
        // 3. 兜底: 按 agent id 硬编码
        _ => match AgentKind::from_agent_id(agent_id) {
            AgentKind::DeepSeekHarness => Ok(Box::new(DeepSeekHarnessAdapter::new(cmd))),
            // ...
        }
    }
}
扩展点：新增 Agent 只需在此函数新增一个分支 (或注册到 ProviderRegistry)，返回新的 Adapter 实现即可。协议层和前端页面无需修改 (OCP)。

三种传输协议：ACP / Serve / JSON-Lines

4.1 AcpAdapter — Agent Client Protocol (JSON-RPC stdio)

通用互操作协议, 通过 stdin/stdout 传输 JSON-RPC 消息。支持两种线路格式:

  • Content-Length (LSP 风格): DeepSeek Harness, Zed agents
  • NDJSON (换行分隔): OpenCode
// ACP 握手流程 (adapter/acp.rs)
1. "initialize"    -> 发送协议版本 + 客户端能力
2. 等待 initialize response
3. "session/new"   -> 创建会话 (传入 cwd, mcpServers)
4. 等待 session/new response (获取 server 侧 session id)
5. "session/prompt" -> 发送用户 prompt
6. 启动 event pump: 读取 stdout -> 翻译 notification -> StreamEvent

4.2 ServeAdapter — opencode serve (REST + SSE)

OpenCode 独有的高性能传输: 一个共享的 opencode serve 进程, 通过 HTTP API 创建会话, 通过 SSE 接收流式事件。

// Serve 传输流程 (adapter/serve.rs)
1. 懒启动: 首次使用时 spawn "opencode serve --hostname 127.0.0.1 --port 0"
2. POST /session         -> 创建会话
3. POST /session/{id}/prompt_async  -> 发送 prompt (支持 per-turn 模型选择)
4. GET /event (SSE)      -> 接收流式事件 (message.part.delta, permission.asked, ...)
5. POST /session/{id}/permissions/{pid}  -> 审批回执
Serve 优势：支持 per-session / per-turn 模型切换 (ACP 上游不支持)。共享进程模型减少启动开销。

4.3 DeepSeekHarnessAdapter — JSON-Lines stdio

参考适配器, 通过 stdin/stdout 传输 JSON-Lines (每行一个 JSON 对象)。

// JSON-Lines 传输流程 (adapter/deepseek.rs)
1. spawn CLI 进程 (通过 core::exec 统一接口)
2. 写入 "init" 行 (项目上下文: project, env, skills, files)
3. 写入 "turn" 行 (用户 prompt)
4. 读取 stdout JSON-Lines -> translate_line() -> StreamEvent

统一事件协议：StreamEvent (Contract C1)

所有 Adapter 将原生输出翻译为 StreamEvent 枚举, 前端只消费这一种格式。这是整个系统的"契约 C1"。

// src-tauri/src/agent/chat/events.rs
pub enum StreamEvent {
    // 会话生命周期
    SessionStart { session_id, agent, model, capabilities },
    ContextInit  { session_id, manifest },
    SessionDone  { session_id, reason },

    // 话轮边界
    TurnStart { session_id, turn_id },
    TurnEnd   { session_id, turn_id, reason },

    // 流式文本
    TextDelta     { session_id, delta },
    ReasoningDelta { session_id, delta },

    // 工具调用生命周期
    ToolStart { session_id, call_id, name, title },
    ToolOutput { session_id, call_id, output },
    ToolEnd   { session_id, call_id, status },

    // 审批 Gate
    RequestApproval { session_id, call_id, tool, title, prompt, diff, cmd },
    UserInput       { session_id, turn_id, prompt },

    // 其他
    CommandRun  { session_id, call_id, cwd, cmd },
    TodoUpdated { session_id, todos },
    FileDiff    { session_id, call_id, path, diff },
    Meta        { session_id, model, usage },
    Error       { session_id, kind, code, message },
}

Page -> Agent 反向通道 (SessionRequest)

多轮对话

当 StreamRequest.session_id 有值时, 命令层直接将 prompt 路由到已有会话:

// commands.rs: agent_stream()
if let Some(sid) = &req.session_id {
    // 路由到已有会话, 不创建新的
    state.agent_chat_manager
        .send(sid, SessionRequest::Turn { prompt, model })
        .await?;
    return Ok(sid.clone());
}

Bridge 与 Manager：事件泵与会话路由

AgentChatBridge — 事件泵

Bridge 的职责极简: 拉取 session.next(), 分配单调递增序列号, 通过 emit 发送到前端。

// bridge.rs
pub async fn run(
    session_id: String,
    mut session: Box<dyn AgentSession>,
    emit: impl Fn(SequencedEvent) + Send + 'static,
) -> Result<(), AppError> {
    let seq = Arc::new(AtomicU64::new(0));
    loop {
        match session.next().await {
            Some(Ok(event)) => {
                let seq_num = seq.fetch_add(1, Ordering::SeqCst);
                emit(SequencedEvent { seq: seq_num, event });
            }
            Some(Err(e)) => { /* emit Error, break */ }
            None => break,
        }
    }
}

AgentChatManager — 会话路由

维护 session_id -> SessionHandle 映射, 支持:

  • register(): 注册会话 + 持久化 ResumeCursor
  • send(): 将 SessionRequest 路由到对应会话的 request channel
  • unregister(): 注销已结束会话 + 标记 store 状态

前端集成：React 调用链路

API 门面 (agentChatApi.ts)

// src/features/agent-chat/api/agentChatApi.ts
import { invoke } from '@tauri-apps/api/core';

// 启动/续写会话
export function startAgentChat(req: StreamChatRequest): Promise<string> {
    return invoke<string>('agent_stream', { req });
}

// 审批回执
export function approveAgentCall(
    sessionId: string, callId: string, allow: boolean
): Promise<void> {
    return invoke<void>('agent_approve', { sessionId, callId, allow });
}

// 取消流
export function cancelAgentStream(sessionId: string): Promise<void> {
    return invoke<void>('agent_stream_cancel', { sessionId });
}

前端数据流

1. 用户输入 prompt -> startAgentChat({ agentId, projectId, prompt, model })
2. 后端返回 sessionId
3. 前端 listen("agent-chat://event") -> 接收 SequencedEvent 流
4. 事件 reducer 根据 type 累积状态:
   - TextDelta -> 追加到消息文本
   - ToolStart/ToolOutput/ToolEnd -> 更新 ToolCard
   - RequestApproval -> 显示审批面板
   - TurnEnd -> 计算 "Worked for Xs" 摘要
   - SessionDone -> 标记会话结束
5. 用户点击审批 -> approveAgentCall(sessionId, callId, allow)
6. 用户发新消息 -> startAgentChat({ ...existingSessionId, prompt })

实战：如何对接一个新的 Agent CLI

以对接一个假设的 my-agent CLI 为例, 完整走一遍对接流程。

Step A: 在 AgentManager 中注册

// manager.rs: default_agents() 中新增
AgentConfig {
    id: "my-agent".into(),
    name: "My Agent".into(),
    command: "my-agent".into(),
    icon: Some("my-agent.png".into()),
    enabled: true,
    chat_transport: Some("jsonl".into()), // 选择传输协议
    is_builtin: true,
    skill_path: Some("~/.my-agent/skills".into()),
    ..Default::default()
}

Step B: 实现 Adapter (以 JSON-Lines 为例)

// adapter/my_agent.rs (新建文件)
use async_trait::async_trait;
use crate::agent::chat::adapter::{AgentAdapter, AgentContext, AgentKind, AgentSession};
use crate::agent::chat::events::{StreamEvent, ...};

pub struct MyAgentAdapter { cmd: Vec<String> }

impl MyAgentAdapter {
    pub fn new(cmd: Vec<String>) -> Self { Self { cmd } }
}

#[async_trait]
impl AgentAdapter for MyAgentAdapter {
    fn kind(&self) -> AgentKind { AgentKind::Custom }

    async fn create(&self, ctx: &AgentContext)
        -> Result<Box<dyn AgentSession>, AppError>
    {
        // 1. spawn CLI (通过 core::exec 统一接口)
        let child = exec::spawn(&ExecTarget::Local, &self.cmd[0], &args).await?;

        // 2. 设置 event channel
        let (event_tx, event_rx) = mpsc::channel(64);

        // 3. 发送 SessionStart + ContextInit
        // 4. 写 init 上下文到 stdin
        // 5. 写 prompt 到 stdin
        // 6. 启动 pump task: read stdout -> translate_line -> event_tx
        // 7. 启动 request channel task: req_rx -> write to stdin

        Ok(Box::new(MyAgentSession { event_rx, request_tx }))
    }
}

// 新增 AgentKind 变体

Step D: 注册 Tauri 命令 (已有的即可)

无需新增命令! agent_stream 会根据 agentId 自动分派到你的 Adapter。前端只需在 Agent 选择器中展示新 Agent。
