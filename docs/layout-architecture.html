③ 双 registry 三层体系（面板如何被找到）

Dock 面板（左右区）

shared/dock/panelMeta.ts纯数据：defaultZone / order / defaultZoneSize + MIN_ZONE_SIZE_PERCENT
↓ 纯 meta，store 直接依赖
app/dock/registry.tstitle / icon / lazy 组件 / wrappers 胶水
↓ DockRegistryProvider 注入 context
layout/DockRegistryContext.tsxuseDockRegistry() 消费 —— layout 对面板清单零感知
OCP：新面板不触碰 layout ESLint 强制 layout 纯度

固定面板（底部）

app/panels/registry.ts{ id, placement: 'left'|'right'|'bottom', lazy Component }
↓ PanelHost 按 placement 过滤渲染
app/panels/PanelHost.tsxSuspense fallback=null；显示状态由各面板 store 自管
↓
AppShell 底部槽位<PanelHost placement="bottom"/> — Task Console + Debug
placement 是 Step 3 统一面板体系的接缝 mock registry 单测护栏

④ 状态源：谁管什么

状态源职责关键事实
dockStore 左右 zone：面板清单 / 激活 / 展开 / 宽度记忆 zustand persist；merge 从 registry 重建面板清单，activePanelId 仍有效才恢复（防悬挂引用），左区展开态重启强制 true
appViewStore 中心视图路由（normal/skills/settings/library） 不持久化；启动时由 useAppShell 把左区 skills 激活态同步回 appView —— 单一中心路由源
taskStore / debugStore 底部面板显隐（consolePanelOpen / panelOpen） 宿主不感知；面板高度各自 localStorage（neeko.task.consoleHeight 等）—— Step 3 时收编进 zone 体系
useZoneExpandCollapse zone 展开/收起 + 双 rAF resize 防「pin tab 后开面板 0 宽」历史竞态；挂起 rAF 随 effect 清理取消（快速展开→折叠不复发）

⑤ 依赖方向（编译期强制）

ui ← layout ← app ← features → shared layout/ 禁止 import features/* 与 app/*（ESLint import/no-restricted-paths）；app 通过 DockRegistryProvider 注入 registry —— 骨架与业务只经 context 相遇

⑥ 扩展指南：加一个面板要改几处？

新增 Dock 面板（进左右区）

  • shared/dock/panelMeta.ts — 加 meta（zone/order）
  • app/dock/registry.ts — 加 title/icon/lazy 绑定
  • 需要 props 胶水时：app/dock/wrappers/ 每面板一文件
为什么这样registry 建表缺失绑定会抛错（buildDockPanelRegistry fail-fast）；layout 与 dockStore 完全不动。

新增底部固定面板

  • 只改 app/panels/registry.ts：加 { id, placement:'bottom', Component: lazy(...) }
  • 组合根 / AppShell / PanelHost 零改动
  • 显隐由面板自己的 store 驱动
护栏PanelHost 过滤逻辑有 mock registry 单测；registry.test 守护 id 唯一 / placement 合法 / Component 存在。

未来 Step 3：bottom 进布局

  • DockLayout 顶层加垂直嵌套 Group，bottom-zone 入布局
  • dockStore 加 bottom zone 独立状态；复用 useZoneExpandCollapse
  • 触发条件：unified-task-hub 面板进底部，或底部需要拖拽/收起
已知风险react-resizable-panels 嵌套 Group 有历史 bug（pin tab → handle 失效）；实施时必须回归 pin-then-open 路径。ZoneId 联合类型已就绪（'left' | 'right'，届时扩展 'bottom'）。
