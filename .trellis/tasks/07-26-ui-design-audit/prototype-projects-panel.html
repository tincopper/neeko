Docker 在列表中的形态

分组键：Docker context（desktop-linux / ssh://host），类比 WSL distro
项目绑定：container（或 compose service）+ 容器内 path
状态：up / exited / restarting，比 SSH auth 更贴近容器生命周期
Worktree 仍是 Git 概念，挂在项目下，与容器无关

Docker 支持：建议信息架构

Environment 第四型 不要做成 SSH 特例

1. 类型模型（与现有对称）

// 现有 ProjectEnvironment = | { type: "Local" } | { type: "Wsl"; distro: string } | { type: "Remote"; host; port; username; auth } // 建议扩展 | { type: "Docker"; context: string; // desktop-linux | ssh://gpu-lab containerId: string; containerName: string; workdir: string; // container path image?: string; composeProject?: string; composeService?: string; }

列表分组顺序建议固定： Local → WSL → SSH → Docker（或按用户最近使用置顶，但默认稳定排序）。

2. 三层对象，不要混层

层含义UI
Connection / Context 如何连上执行环境 SectionHeader：WSL distro / SSH host / Docker context
Project 某环境下的代码根 项目卡：name + path + agent/IDE
Session / Worktree 同一项目的并行工作区 缩进行：main session + git worktrees

Docker 的 container 属于 Connection 细节（或 Project.environment 字段）， 不是第四层“再套一层 folder”。Compose 多服务时：一个 service ≈ 一个 project 绑定，或一个 container 入口。

3. 与 SSH / WSL 的边界

  • WSL：Windows 上的 Linux distro，路径在 distro 文件系统
  • SSH：远程机器 shell，认证是一等公民
  • Docker：容器运行时；可能 local engine，也可能 DOCKER_HOST / context 指向远程
  • 远程 Docker 若经 SSH 隧道，UI 仍显示 Docker，副标题写 context，避免用户以为是普通 SSH 项目

4. 添加流（Add 菜单）

Add Project ├─ Local folder… ├─ WSL distro… ├─ SSH remote… └─ Docker… ├─ Pick context (desktop / remote) ├─ Pick running container │ └─ or Compose service ├─ Pick workdir in container └─ Bind default Agent / IDE

空态第四按钮用 ghost：「从 Docker 容器添加…」，未实现前可 disable + tooltip。

5. 状态与操作

  • 状态点/胶囊：up / paused / exited / not found
  • 容器退出：项目仍保留，点击时引导 Start container / 重选容器
  • 终端：docker exec -it 进 workdir（或 attach 策略可配置）
  • Git：在容器内 git，或挂载 volume 后与本地 git 二选一（需产品定默认）
  • IDE：优先 Dev Containers / 附加到容器；失败再 fallback 打开挂载路径

6. UI 细则（与现列表一致）

  • Section 色点：Local 绿 / WSL 蓝 / SSH 黄 / Docker 青
  • 禁止 emoji 当主图标；用简洁 glyph 或官方 Docker 单色标
  • 副标题可显示 image 或 compose/service，避免和 branch 抢第一行
  • 过滤 chip 增加 Docker；搜索匹配 name / container / context
  • 规模大时 Section 可折叠，记忆每 context 的 collapsed 状态

7. 分阶段落地

  • P0：只读发现 running containers + attach workdir + exec 终端
  • P1：context 切换、容器状态刷新、exited 恢复
  • P2：Compose 服务视图、Dev Container 元数据、远程 context
设计原则一句话： 环境是「连接与执行面」，Worktree 是「同一仓库的并行检出」，Docker 是新的环境类型而不是新的项目树范式。 这样 Local / WSL / SSH / Docker 共用同一套 Section → Project → Session 组件，后续再加 Podman / DevPod 也只是 environment variant。
